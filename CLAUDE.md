# CLAUDE.md — Orchestrator rules (Claude Code)

Project: **dataceam.com** — Astro (static) + TypeScript + Tailwind v4, hosted on Cloudflare Pages (project `dataceam-site`). Current state: `ops/STATUS.md`.
Owner/approver: **Jawad**. Implementer: **Codex CLI**. Full spec: `../dataceam-development-plan.md`.

## Rules
1. Read `ops/TASKS.md` and the content rules below before starting any work.
2. **Never write application code.** Every code change (pages, components, styles, scripts, config, tests, `package.json` scripts) goes to Codex as a task spec, review feedback included.
   - Carve-out: CC writes control files only: `CLAUDE.md`, `AGENTS.md`, `ops/*`, `.claude/*`, page copy in `content/*.md`, and entries (data and copy only, never code) in `src/content/{tracks,repos,guides}/` (Jawad, 2026-11-21).
   - Guide images generated by `npm run guide:images` (`src/assets/guides/`, `public/og/guides/`) count as content (Jawad, 2026-11-24).
   - T-025/T-026 code was written by Claude subagents, one time, because Codex was at its usage limit (Jawad, 2026-11-24). The rule stands for everything else.
3. One task = one branch = one PR. Branch name: `task/<id>-<slug>`.
4. After every Codex attempt: review the diff against the spec, then run `npm run check`.
5. At most **3 Codex attempts** per task. After that, stop and report to Jawad with the diff, the errors and a proposed fix.
6. Log every Codex run as a row in `ops/codex-log.md`.
7. Never merge to `main`, push to `main`, deploy to production, change DNS, delete anything or touch secrets without Jawad's explicit **"approve"** in chat — every time. (`main` has no GitHub branch protection; this rule is the protection.)
   - **Standing exception, guide routines (Jawad, 2026-11-24):** the two daily cloud routines (01:00 and 14:00 Malta) may publish one guide each to `main` without a new "approve", only through `npm run guide:publish`, only for the paths that script allows (the guide, its images, its infographic JSON, the guide log, link-backs in up to 3 live guides; when a guide is parked, only `ops/guides/parked.json` and its saved draft in `ops/guides/drafts/<slug>/`, Jawad 2026-11-25), and only when the lint and `npm run check` pass and every reviewer point has been fixed or cut (Jawad 2026-11-25, T-031). Runbook: `ops/guides/publish-daily.md`; off switch: create `ops/guides/PAUSED`. When the queue is empty they stop and report. This covers nothing else.
8. The content rules below are hard requirements. Reject any diff that breaks them.
9. Keep summaries to Jawad short: what changed, the preview URL, anything that needs his decision.

## Dispatching to Codex
```
codex exec -C "$(git rev-parse --show-toplevel)" -s workspace-write "<task spec>" < /dev/null   # stdin must be closed or codex waits forever
```
- Codex has no network; CC runs `npm install` itself before/after dispatch when deps change.
- Paste the full task spec from `ops/TASKS.md` plus any review feedback.

## Quality gates
- `npm run check` — fast gates (build, astro check, eslint, prettier, content-lint, links). Run after every Codex attempt.
- `npm run check:full` — `check` + Lighthouse CI + axe + gitleaks. Run by `/ship`.

## Content rules (hard)
Positioning (Jawad, 2026-11-21, redesign brief `ops/REDESIGN-2026-11.md` §1 and §6, T-021): Dataceam is a free AI-learning hub (guides, career tracks, repos) that is also a **referrer only** for AI-training work (`/jobs/`) and data licensing (`/companies/`).
- **Voice "we, Dataceam" everywhere.** "Syed Jawad" appears only on `/disclosure/` (and the privacy policy, which must name the data controller). No location in visible copy; Malta appears only in the privacy policy.
- **The full referral disclosure lives on `/disclosure/`** (copy: `content/disclosure.md`), not in the footer. The footer links to it. `/companies/` and `/jobs/` carry an "Independent referrer" badge and link to it.
- No buyer or platform logos or names (micro1, Mercor, DataFactor, Lodex or others) in visible copy. Referral URLs in links and in `src/config/site.ts` (`expertPlatforms`) are fine; content-lint masks URLs for this rule only. On `/jobs/` the platforms are labelled "Platform 1" and "Platform 2".
- **Referral links live only on `/jobs/`, behind the consent box.** Home, tracks, guides and `/free/` short links send people to `/jobs/`, never straight to a platform. If a platform link is ever needed elsewhere, gate it with the same consent text in a native `<dialog>` (brief §3.5).
- Never claim to be a buyer's or platform's partner, agent or representative, and never imply Dataceam hires, screens or pays anyone. Never describe buyers as "vetted", "our buyers" or "current buyers", and never describe data handling Dataceam doesn't do (cleaning, PII stripping, encrypted access). Buyer commitments are framed as "get these in writing".
- Required disclosure lines (exact, enforced by content-lint):
  - `/companies/`: *"Dataceam is a referrer only. If a company we introduce signs with a buyer, the buyer may pay us a referral fee. You pay nothing for the introduction."*
  - `/jobs/`: *"Dataceam is a referrer only. If you're hired through one of these links, the platform may pay us a referral bonus. You pay nothing."*
  - FAQ: *"Dataceam is a referrer only."* and *"If a deal or a hire happens, the buyer or platform may pay us a referral fee. It costs you nothing."*
  - Next to every referral-link block (Home AI jobs strip, track "Next step" card, `/jobs/`, anywhere else): *"Referral links: we may earn a fee if you join through them."* plus a "Referral disclosure" link to `/disclosure/`. Pages with `data-page` home, track, companies or jobs must link to `/disclosure/`.
- Amounts: only the buyers' published tiers ($50K+ / $500K+ / $1M+; "from around $50,000 to over $1 million"), always next to "not a promise" / "each buyer prices each company itself". No promised or guaranteed amounts.
- `/jobs/` (was `/experts/`, which 301s there; Jawad, 2026-11-14): info and links only — work areas with typical pay (from the platforms' public listings, dated, "rates change"), one general referral link per platform, and a consent box that must be ticked before the links work (nothing recorded). No job list, no per-job links, and never collect résumés or candidate data (GDPR controller duties; Malta employment-agency licensing risk).
- **Free-first wording.** Lead with what's free; never call a paid thing free; state the paid part once, plainly ("Free to study · exam optional (paid: $X)"). Never "free certification" when the exam is paid, never "unlimited" when there are limits. A course marked free links to the provider page that shows it is free.
- **Guides are long-form (Jawad, 2026-11-24):** 1,200–3,000 words, plain English for readers with no IT background, American spelling, sources, infographics, FAQ. Rules: `.claude/skills/write-guide/`. Every internal URL ends with a slash (enforced by content-lint).
- **Facts have sources.** Every fact on tracks, repos and guides has a source and a check date. No entry goes `status: live` with `[h]`/`[price]` placeholders: research them, or drop the course. Until then entries stay `status: soon` ("Coming soon", noindex, out of the sitemap).
- **Logos are credits.** Course providers, companies, repos and tools we recommend may be named and shown with their official, unaltered SVG (dark version of monochrome marks on the light background), never as our branding and never implying a partnership or endorsement. The name ban above covers buyers and AI-jobs platforms only.
- No urgency or get-rich language. No LinkedIn anywhere (links, courses or guide topics). Never use the term "data broker".
